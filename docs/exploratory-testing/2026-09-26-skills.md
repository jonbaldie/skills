## Journey 1: install

Goal: skills from this checkout are on disk for the named agent, and
OpenCode can list them. `in-progress/` and `deprecated/` stay out.
Documented command, declining prerequisites:

```text
cd <git project>
printf 'n\n' | ../jonbaldie-skills/install.sh --agent opencode --yes
```

Exit 0. Twenty-one `SKILL.md` files under `.agents/skills/`. No
`ship-spec` or `tutor`. Re-run exited 0 and left the same set.
`opencode debug skill --pure` listed the project copies. `ship-pr` was
the exception: OpenCode kept the already installed copy at
`~/.config/opencode/skills/ship-pr/SKILL.md` and did not also list the
project copy. That matches OpenCode's unique-name rule, not an installer
miss.

Variations, all from a clean directory:

| Action | Result |

| `--skill does-not-exist` | Exit 1. `No matching skills found`. No `SKILL.md` left behind. |
| `--skill options` | Exit 0. Only `options`. |
| Path with a space | Exit 0. OpenCode listed the project skills. |

## Usability

The one-liner prompt says `[y/N]` and, with no terminal, answers `y`.
The checkout installer with stdin closed answers no. Those two documented
install paths disagree when nobody is there to type.

Global OpenCode install lands in `~/.agents/skills`, which OpenCode does
load. It does not land in `~/.config/opencode/skills`. The README only
calls out the Cursor case.
